# 原生状态自适应监控（Windows / WSL / SSH）

此功能在现有**用户主动启用的原生连接**上运行。一个来源可同时接入多个已有端点，详见 [覆盖率与本地端点诊断](diagnostics-native-state.md)。不启动、恢复、接管或订阅 Codex 线程；只使用已有的只读 initialize、thread/loaded/list、thread/read(includeTurns:false) 白名单。

## 调度与安全边界

- 已确认活跃线程（包括等待输入/审批）保持最短每 **3 秒**核验；稳定空闲、notLoaded、无法识别或读取失败的线程降为 **12 秒**，不改变原有 **15 秒**状态证据过期时限。线程繁多时最多每轮 64 次读取，4 并发、8 秒轮询截止，过期证据回退日志。
- 已加载列表在有近期活跃线程时每 **10 秒**审计，完全安静时最长 **30 秒**；日志出现新线程或已观察文件变更时提前审计。列表不完整不代表线程结束。
- 若客户端从当前已连接服务被动收到 thread/status/changed、turn/started 或 turn/completed，只针对**当前来源已知 UUID**安排提前核验。不把消息字段直接当状态；必须再执行 thread/read，核对身份与最新文件时间。
- 收到服务主动发来的输入/权限请求时，不回复、不审批、不执行操作；不自动发送 thread/subscribe、thread/resume 或 turn 写操作。没有被动消息仍依靠定期轮询。
- 初次接入、断线重连与移除来源时仍建立静默基线，不补报已有等待。旧连接的迟到消息被忽略；大量线程优先读取未观察及过期目标，保留有界轮转公平性。
- 闲置降频**不允许使用旧状态**：原生样本超过 15 秒即失效，回退日志判断。

## 验证

诊断中心每个原生来源增加两个累计指标：

- **状态读取**：实际发出的 thread/read 次数（不是 WebSocket 总帧数）。
- **被动唤醒**：通过来源 UUID 筛选的被动状态提示数量（提示本身不代表确认了一次状态变化）。

可观察闲置期间状态读取计数增速是否减小；活跃任务及提问仍应及时更新。配置与原有 GPU 兼容方案不变。

此功能不宣称所有 Codex 客户端都会向额外的只读连接广播状态通知；没有事件时只依靠保守轮询。未在用户实际的 Windows + WSL + SSH 环境进行资源基准测量。
