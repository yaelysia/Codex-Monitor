# 诊断中心与可选原生状态

入口：系统托盘右键 → **诊断中心 / 原生状态**。诊断界面按需创建，关闭后释放窗口；原有 Monitor 与悬浮窗不受影响。本阶段不安装 VS Code 辅助扩展，也不修改 Codex。

## 诊断中心

- 健康总览：按来源分别查看采集健康、文件事件通道、最近采集时间、扫描耗时、stat 与缓存计数，以及原生连接的已加载 / 匹配 / 有效覆盖数量。
- 状态轨迹：保留本次 Monitor 运行中最近 400 条元数据变化，可按会话筛选、拖动回看位置、查看当前窗口绑定解释。清空仅影响诊断记录，不清除通知或操作会话。
- 脱敏导出：点击按钮后在系统保存对话框选择 JSON 文件。主进程重新取得报告并只导出白名单字段；不接收渲染器指定的任意文件路径，不自动上传。

导出包含时间、计数、状态、证据类别和本次运行的匿名来源 / 会话编号。不包含原始 UUID、会话标题、目录、提示词、工具参数、连接端点、原始错误、HWND 或 PID。窗口中的标题与绑定说明用于本机查看，不进入导出报告。该报告是有界的状态和通知决策轨迹，不是完整原始日志、对话回放或操作系统通知实际显示的证明。`popup-requested` 只表示程序请求了系统弹窗。

## 原生状态接入

默认不启用、不扫描端口、不创建服务。**同一来源可以配置多个独立的现有 App Server 端点，总连接数最多 8 个**，不能重复配置同一来源的同一端点。旧设置自动兼容；没有自动订阅、恢复或接管线程。

1. 在「原生状态接入」添加已采集的来源。
2. 本地可选择当前 CODEX_HOME 的已有控制套接字，或明确填写本机绝对套接字路径。
3. WSL / SSH 可填写已建立的本机回环 WebSocket 转发地址，例如 `ws://127.0.0.1:17891/`。转发必须连接该客户端**已经运行**的实际服务；Monitor 不建立 SSH 转发，也不启动替代 App Server。
4. 可点击「检查已知本地共享端点」：只对当前本地 CODEX_HOME 下固定的控制套接字路径做存在性检查，不扫描其他目录、端口或进程。不等于服务真正可用；发现候选后可添加但必须手动启用并保存。
5. 同一来源若有多个已经对外开放的独立服务，可分别添加其本机回环端点。勾选启用并保存，在健康总览检查连接、匹配、覆盖原因。连接成功但匹配为零，不代表现有会话已接入。

自动路径为当前本地 Codex 根目录下的 `app-server-control/app-server-control.sock`。不存在、协议不兼容或客户端未开放共享端点时，显示降级并继续原有日志监控。不同 Desktop / VS Code / CLI 实例不一定共享服务；在私有 stdio 中运行、未开放可访问控制端点的实例仍无法从外部读取原生状态。多个服务若都报告同一来源的同一 UUID，按配置顺序选择首个新鲜证据，后续作为回退，**不会把同一会话重复计入原生覆盖数**。远程配置以用户选择的来源为范围，并以 thread ID 精确匹配已扫描会话，不跨来源合并相同 UUID。

### 只读边界

复用仓库现有探针的 WebSocket / JSON-RPC 客户端。仅允许 `initialize`、`thread/loaded/list`、`thread/read(includeTurns:false)` 和初始化完成通知。不调用 `thread/resume`、订阅、`turn/start`、配置修改或审批回答。服务端发送的输入 / 审批请求不会代答；连接层不保留原始消息。端点必须为本机套接字或无凭据、查询参数及自定义路径的本机回环 WebSocket；拒绝公网明文、网络共享路径和端点内嵌凭据。

这是定期读取原生状态摘要，**不是**保证全局实时订阅所有客户端的事件流。每批完成约 3 秒后再次采集，已加载列表约 10 秒复核一次；单批最多 64 个匹配会话、4 个并行请求，较多会话轮转补齐。请求有超时，单批设 8 秒上限；失败按 4 至 60 秒退避。当前原生证据最多保留 15 秒，连接断开、来源失联或身份不匹配即回退原有日志证据。设置停用后关闭连接，不改变客户端会话。

### 状态和提醒语义

- `active` 且无等待标志：原生确认当前线程活跃；不会据此清除已经落盘的异步待回答提示。
- `waitingOnUserInput` / `waitingOnApproval`：显示原生待处理。初次连接或重连只建立基线，不补发已有等待状态；之后确认的新等待变化进入现有提醒收件箱，沿用通知类型、静音、前台抑制和自动已读规则。
- `idle`：只证明当前空闲，不证明某一轮成功完成。有明确日志结束证据时保留其结果，否则显示未知并解释原因，不生成伪完成提醒。
- `systemError`：显示服务报告异常，但不伪造某轮失败事件。`notLoaded`、不认识的状态或 activeFlags 不提供正面的执行中判断。
- 新的文件事件优先于更早开始的原生读取，直到下一次原生确认；已确认的窗口身份和同窗口多对话歧义规则没有放宽。

## 验证边界

自动化测试验证协议白名单、实际 WebSocket 握手的既有探针、来源隔离、分页 / 限额、基线与重连、过期回退、等待去重、设置校验、导出脱敏和界面入口。CI 不能证明用户机器上每个客户端已经开放共享服务，也不替代实际窗口、连接覆盖与提醒验收。没有开展用户电脑的 CPU / 内存基准测试。
