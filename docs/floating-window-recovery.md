# 悬浮窗长期运行失效的恢复机制

在运行中出现悬浮窗消失、空白、无法交互时，**无需重启整个 Monitor**。系统托盘右键 → **修复悬浮窗（重建窗口）**。此操作会重新创建独立的 Electron 悬浮窗及渲染器，保留停靠的屏幕边缘、Y 位置、大小、透明度和主题；显示为收起状态，不抢占当前应用的键盘焦点。不会中断后台 Codex 扫描与通知。

## 自动恢复

- 仅在用户已设置为“显示悬浮窗”时工作。每 30 秒检查原生 HWND 的可见性、WebContents 是否被销毁、原生置顶、透明度与是否仍在可见显示区域。
- 渲染进程崩溃、页面加载失败/被拒绝、长时间未完成加载、持续 15 秒无响应、原生窗口意外销毁，触发延迟约 1.5 秒的悬浮窗重建。不是只调用 `showInactive()` 复用可能已经崩溃的渲染器。
- 自动重建上限：滚动的 10 分钟内最多 3 次；防止 GPU/Chromium 连续故障导致重启风暴。超过上限只记录一次警告，可随时使用托盘的手动重建按钮。重建不修改 GPU 沙箱设置。
- Windows 唤醒、接入/拔除显示器、分辨率变化时重新对齐屏幕位置、恢复原生置顶，而不是强制把 Monitor 带到前台。
- **用户主动隐藏后绝不自动显示**：停止健康检查，取消未触发的恢复和无响应计时；隐藏超过一分钟的既有渲染器释放逻辑保持不变。用户再次显示时发现损坏会新建。
- 所有计时器在完全退出时清理；旧渲染器的迟到退出/关闭事件不能影响新窗口。

## 验证范围

Windows/Ubuntu Vitest 模拟生命周期测试覆盖崩溃、窗口意外关闭、被系统隐藏、GPU/加载失败后的窗口重建、显示器复位、隐藏后的抑制、恢复次数限制以及托盘强制重建。CI 仍执行已有的真实 Windows Electron/GPU 启动冒烟测试，但该测试**不模拟用户电脑长时间运行后发生的原生 DWM/GPU 故障**。暂无法确定其精确根因；这次重点修复不可恢复的缺陷，并提供独立自救入口。

若问题仍复现，请保留监控进程并观察托盘**修复悬浮窗**能否恢复，同时在 `npm run dev` 所在的 PowerShell 终端查看是否出现 `Floating window` 相关警告（不包含会话正文）。
