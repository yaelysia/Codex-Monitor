# WSL / SSH 目录增量索引（2026-10-20）

在 [远程 JSONL 解析缓存](remote-scan-performance.md) 上进一步减少无关文件元数据访问。**没有新增远程服务、持久缓存文件、依赖、Hook 或 Codex 端改动**；仍通过现有一次性 Python 扫描器与临时 inotify watcher 工作。

## 设计

- 初次全量扫描、watcher 尚未就绪时，仍按原始 `os.walk` 顺序发现最多 10,000 个候选，并流式选出最近 200 个、额外核验最多 16 个已固定活跃会话。每个来源仅在**watcher 就绪之后**完成一轮新的可信全量扫描，才启用该来源的内存候选索引。
- 已有 inotify watcher 对常见的 `IN_MODIFY` / `IN_CLOSE_WRITE` / `IN_ATTRIB` 事件发送最多 64 个经过格式检查的 `YYYY/MM/DD/*.jsonl` **相对定位符**。这些定位符既不是绝对目录，也不是 JSONL 内容；从 SSH/WSL stdout 收到后再次进行类型和边界校验。
- 只有全部变动都属于先前最近 200 个候选时，下一次事件扫描才把短索引交给原来的 Python 一次性进程；Python 必须再次核对真实根目录的哈希、路径无越界、真实文件存在、类型、mtime 未回退，并按完整扫描保存的目录发现次序保持毫秒级 mtime 相同时的顺序。失败时**同一次调用内直接进行全目录扫描**。
- 新建/删除/重命名文件、新目录、无效或未知路径、超出 watcher 限额、inotify 队列溢出、监听断开/重启、来源失败、配置/根目录切换、扫描期间出现新事件，都会使候选索引失效。一个 watcher 消息校验失败同样不能保留旧索引。
- **60 秒周期性全量审计不变**，监控的 12 秒断线轮询、活跃会话固定路径核验、状态时间过期、VS Code 长日志深度提问检查以及原生/通知规则均未放宽。增量扫描不会续期全量索引；额外有 70 秒最长索引有效期防守。
- 目录索引和此前的解析缓存均仅保存在 Windows Monitor 进程内存中，按来源与传输配置隔离，不写进远程目录；不向 UI 或脱敏诊断报告输出相对会话路径。远程扫描脚本只运行当前这一次扫描，不在远程安装常驻 daemon。

**注意：** 目录索引是对**当前最近 200 个候选的受限快速路径**，并非对任意历史文件的完整目录索引。变动发生在不属于该候选集的旧会话、新建文件或复杂目录操作时优先全量，避免漏掉第 201 个候选或破坏排序。

## 可复现基准

```powershell
python scripts/benchmark-remote-scan.py --files 10000 --repeats 3
```

2026-10-20 GitHub Actions Ubuntu 运行器，Python 3.12，**10,000 个合成 JSONL，最近 200 个较大日志，3 次无埋点测量中位数**；校验输出与无缓存全量结果逐条一致。以下测量只涉及 Python、本地临时目录和文件系统：

| 场景 | 耗时中位数 | statCalls | directoriesEnumerated | JSONL 打开数 | 读取量 |
|---|---:|---:|---:|---:|---:|
| 冷扫描（当前实现） | 413.57 ms | 10,200 | 4 | 200 | 62.5 MiB |
| 未变化：仅解析缓存 | 88.13 ms | 10,003 | 4 | 3 | 0.94 MiB |
| 未变化：目录索引 + 解析缓存 | **51.61 ms** | **203** | **0** | 3 | 0.94 MiB |
| 一条日志追加：仅解析缓存 | 90.24 ms | 10,004 | 4 | 4 | 1.25 MiB |
| 一条日志追加：目录索引 + 解析缓存 | **53.48 ms** | **204** | **0** | 4 | 1.25 MiB |

该样本中新增目录索引将温扫描的**候选 stat 统计数量减少约 98%**，Python 采集器耗时降低约 **40–41%**，不是整机或 SSH 全链路降幅。三个有意重解析的旧文件跨越了状态年龄边界，不能为了缓存命中而冻结状态。基准并不包含 Windows `wsl.exe` 启动、SSH 建连、传输 RTT、Electron 开销、CPU/RAM 长期表现，也不使用耗时门槛判断 CI 通过。基准运行记录见 PR #23 及其 Ubuntu Verify 日志。

## 诊断与回退

诊断中心 → 健康总览会显示每个来源的全量/增量模式、总耗时、遍历目录数、候选 stat 与 JSONL 解析缓存命中数。初次启动、来源重连、手动刷新以及约 60 秒完整审计出现“全量”是**预期行为**。没有受信任的 inotify 变更范围时，不应该为了提高命中率强行启用增量。
