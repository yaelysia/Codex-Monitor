# WSL / SSH 扫描性能优化

本轮针对远程 JSONL 的重复读取与解析，不修改状态机、原生连接、窗口关联、通知规则或原有扫描节奏。不安装远程依赖、服务、Hook 或缓存文件；Python 仍通过原来的 SSH / WSL stdin 一次性运行。

## 实现与边界

- **本节记录的是 2026-10-19 的远程解析缓存阶段**：当时每次扫描仍按原目录顺序发现最多 10,000 个文件，保留最近 200 个及最多 16 个历史活跃会话定位；使用 `heapq.nlargest` 流式选择，但仍需遍历目录。2026-10-20 已在此基础上增加安全增量候选索引，见 [远程目录增量索引](remote-directory-index.md)。
- 事件/单来源扫描向原有进程发送上次解析的相对路径、会话 ID、文件签名及源时间有效期，不发送标题、提问或对话正文。远程验证真实根目录摘要、设备/inode、大小、纳秒 mtime/ctime、模式和有效期，只有完全匹配才返回引用；主进程必须持有对应来源的原始解析才能复用。
- 手动/周期性全量扫描不使用引用。缓存最长 60 秒、不随命中续期；跨越执行中、等待、提问或深层核验的年龄边界会重新解析，源时钟回退也不复用。文件读到一半发生写入时不生成可复用签名。
- 命中后重新计算文件年龄与最近用户输入年龄；标题和 SQLite 来源补全仍每次查询，删除重命名记录后也能退回原始日志标题。活动推断与原生状态投影不写入解析缓存。近期截尾的 VS Code 会话不缓存，保留原有每批八个深层提问核验的次序与限额。
- 主进程缓存按来源和传输/根目录配置隔离；最多 8 个来源、每源 216 条、每源序列化元数据预算 512 KiB（不是整机堆内存承诺）。失败清空复用信息，迟到并发结果不能覆盖新一代缓存，消失的会话不会从缓存复活。
- 短文件的头尾重叠区只读取一次。所有尾部读取指定长度，不会因文件并发增长而无限读取。

诊断中心已有的每源 `statCalls`、`parsedFiles`、`cacheHits`、`indexedFiles` 也可用于 WSL / SSH。此历史阶段仅有 `indexMode=full`；新目录索引启用后才可能出现 `incremental`，并单独显示目录枚举次数。stat 计数是显式候选/固定会话检查及解析后 fstat，不代表进程所有文件系统调用。

## 可复现基准

```powershell
python scripts/benchmark-remote-scan.py --files 10000 --repeats 3
```

脚本只在临时目录生成合成日志，不读取真实 CODEX_HOME；比较输出字段与顺序，不设置不稳定的耗时通过阈值。默认以当前采集器的无缓存路径比较。与旧版本比较时，把旧 `collector/scan.py` 导出到独立文件，增加 `--baseline <文件路径>`。

2026-10-19 在助手 Linux 测试容器、Python 3.13.5 上，与 `c09a308c7e6e51cb24002016da4ae23cd102f580` 的原始采集器（blob `d2f895d3725981612c43186e4a25af1b64cb4d63`）比较：10,000 个候选、最近 200 个较大日志、3 次重复的中位数；计数单独测量，不计入计时。

| 场景 | 中位耗时 | 打开日志数 | 读取日志字节 | 重新解析 / 复用 |
|---|---:|---:|---:|---:|
| 旧版全量 | 1889.54 ms | 200 | 65,536,000 | 200 / 0 |
| 新版冷扫描 | 1395.43 ms | 200 | 65,536,000 | 200 / 0 |
| 新版未变化扫描 | 144.51 ms | 3 | 983,040 | 3 / 197 |
| 新版一条日志追加 | 142.90 ms | 4 | 1,310,720 | 4 / 196 |

未变化扫描中的三条重读是合成数据刚好跨越年龄边界，属于有意保留的重新核验，不能为了命中率冻结状态。四种场景均与旧版相同源时间的输出逐字段、逐条顺序比较一致。另有 30 条同龄日志的确定性回归断言：未跨时间边界且没有变化时，日志读取与解析均为零。

这些耗时只覆盖本地 Python / 文件系统采集，不包含 SSH 建连、WSL 启动、JSON 传输、Electron 全链路或用户电脑 CPU/RAM；读取字节是程序读取量，不等同物理磁盘流量。真实收益取决于历史会话数量、日志大小、活跃比例和连接开销。近期大 VS Code 日志因上述核验边界，缓存收益较小。
